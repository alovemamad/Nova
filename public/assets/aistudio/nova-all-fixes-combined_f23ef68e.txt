BUG 1 - Phones that updated through the in-app updater are stuck in landscape
======================================================================
Root cause (confirmed from code):
 a) Phone clients v1.0.9-v1.0.11 have the OLD GitHubUpdater.selectBestApkAsset with NO "-TV-" filter. It loops over ABIs and takes the first asset whose name contains "arm64-v8a" etc. The release now contains NovaVPN-TV-<tag>-arm64-v8a.apk (and sorts before NovaVPN-<tag>-...), so those phones downloaded and installed the TV APK.
 b) The TV APK (app/src/tv/AndroidManifest.xml) hard-codes android:screenOrientation="landscape" on MainActivity and MainActivity also sets requestedOrientation=LANDSCAPE when DevicePlatform.isTv(), and DevicePlatform.isTv() returns true whenever BuildConfig.IS_TV is true. So the TV APK on a phone = landscape + TV UI forever.
 c) The v1.0.12 TV APK's updater picks only "-TV-" assets, so those phones never return to the phone build.

Fixes:
 1. app/src/tv/AndroidManifest.xml: REMOVE android:screenOrientation="landscape". Never lock orientation in the manifest.
 2. DevicePlatform.isTv(context) must be based on the REAL device, not on the build flavor:
      true if PackageManager.FEATURE_LEANBACK  OR  UiModeManager.currentModeType == UI_MODE_TYPE_TELEVISION  OR  (BuildConfig.IS_TV AND the device lacks FEATURE_TOUCHSCREEN).
    Remove the unconditional `if (BuildConfig.IS_TV) return true`. Cache the result.
 3. MainActivity: lock landscape only when DevicePlatform.isTv(this) is true (already so, keep it); otherwise do not set requestedOrientation at all (and explicitly leave the default UNSPECIFIED).
 4. Updater: select assets by the REAL device type, not BuildConfig. checkLatestRelease/parseLatestReleaseJson/selectBestApkAsset get `isTv` from DevicePlatform.isTv(context) (pass it from the caller; keep the parameter for tests). Result: a TV APK that is installed on a phone will update itself to the PHONE APK on the next release (same applicationId and same signature, so Android accepts it).
 5. NEW TV ASSET NAMES so the OLD clients (v1.0.9-v1.0.11, which we cannot change) can never match a TV asset. The old code matches any name containing: arm64-v8a, arm64, aarch64, armeabi-v7a, armeabi, armv7, x86_64, x64, amd64, x86, and prefers names containing "universal". So TV assets must contain NONE of those strings. Use:
        NovaVPN-TV-${TAG}-a64.apk      (arm64-v8a)
        NovaVPN-TV-${TAG}-a32.apk      (armeabi-v7a)
        NovaVPN-TV-${TAG}-intel.apk    (x86_64)
        NovaVPN-TV-${TAG}-all.apk      (universal)
    Phone assets keep their current names. Update android-ci.yml (copy_split_apks for the TV build must rename abi tokens with this mapping), the release notes line, and selectBestApkAsset: TV mode maps a64->arm64-v8a, a32->armeabi-v7a, intel->x86_64, all->universal and considers only names containing "-TV-"; phone mode ignores names containing "-TV-".
 6. Update GitHubUpdaterTest: (a) release with phone + TV assets -> phone picks phone asset for each ABI + universal fallback; (b) TV picks the TV asset for each ABI + "all" fallback; (c) release with NO TV assets -> TV mode returns null asset without crashing; (d) simulate the OLD algorithm on the new asset list and assert it never selects a "-TV-" asset (write the old matching logic inside the test); (e) SHA256SUMS.txt is never chosen.
 7. Also run the phone-build unit tests/assemble with `-PtvBuild=true` NOT set and confirm the merged phone manifest has no LEANBACK_LAUNCHER, no screenOrientation, and that the TV merged manifest has no screenOrientation either.
