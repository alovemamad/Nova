PART 3 - D-pad / remote UI (this is the big part)
------------------------------------------------------------
Nova is a touch-first Compose UI (Glass theme: GlassKit, GlassTabBar, GlassBackdrop). On TV:
1. Every interactive element must be focusable and show a clear focus state (bright glass outline/scale 1.05 + brighter tint). Implement ONE reusable modifier, e.g. `Modifier.tvFocusable(onClick)`, in the glass package and apply it to: Connect button, profile cards, switches/toggles, text-field rows, dropdowns, dialog buttons, tab items, list rows in Settings/Stats/Profiles.
2. Bottom tab bar: on TV, show it as a plain focusable row (or a left/top navigation rail). NO drag gesture on TV: LEFT/RIGHT moves focus between tabs, OK/ENTER selects. Tab tags `tab_*` must stay unchanged.
3. Default focus: on first composition of each screen request focus on the main action (Home -> Connect button). Use FocusRequester + `focusProperties`/`focusGroup` so that DOWN/UP/LEFT/RIGHT navigation is predictable and never gets trapped. Dialogs (ProfileEditorDialog, GeoResourcesDialog, update dialog) must take focus when opened and return it when closed; BACK must close them.
4. Lists must scroll to keep the focused item visible (bring-into-view) - LazyColumn with focus should auto-scroll.
5. Text input: on TV, text fields open the system IME with the remote. Also provide alternatives to typing a profile: "Import from clipboard" (if available), "Import from URL/subscription link", and "Import from file". QR scanning by camera is not available on TV - hide the camera/QR-scan button on TV. Nova currently only decodes QR from an image (zxing core), so make sure nothing on TV launches a camera intent. Keep "show my profile as QR" (so a phone can scan it) if it exists.
6. Layout: TV is landscape 1080p/720p at 10-foot distance. Use larger text (min body ~16sp, titles 24sp+), 48dp safe-area padding (overscan), and a max content width (~960dp) centered, so phone layouts do not look stretched. The existing phone layout must remain unchanged when IS_TV is false.
7. Performance: remove or reduce heavy blur/lens effects on TV (many TV SoCs are weak). When IS_TV, use the "reduceTransparency"/plain glass path of GlassTheme by default (solid translucent panels, no real-time blur) and keep the wallpaper gradient.
8. Orientation: lock TV build to landscape.

PART 5 - In-app updater must not mix phone and TV APKs (IMPORTANT)
------------------------------------------------------------
File: app/src/main/java/app/novavpn/core/net/GitHubUpdater.kt (`selectBestApkAsset`). It chooses by ABI alias and falls back to "universal" or an APK without an ABI tag. With TV assets in the same release, a phone could download `NovaVPN-TV-...-universal.apk` (or the reverse).
- Phone build (IS_TV=false): ignore every asset whose name contains `-TV-` (case-insensitive).
- TV build (IS_TV=true): consider ONLY assets whose name contains `-TV-`; same ABI selection logic inside that set.
- Make the function pure/testable by passing `isTv` as a parameter (default BuildConfig.IS_TV).
- Extend app/src/test/java/app/novavpn/core/net/GitHubUpdaterTest.kt: a release containing both phone and TV assets -> phone picks only phone asset for arm64-v8a, armeabi-v7a, x86_64 and universal fallback; TV picks only the TV one; a release with NO TV assets -> TV returns null (no update, no crash); SHA256SUMS.txt is never chosen.
- On TV, the update flow's "install" step uses the same installer path; guard the unknown-sources settings intent with try/catch as described above and show a message with the release page URL if it cannot be opened.
